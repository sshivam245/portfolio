The challenge

Three Layers of Operational Complexity — All Unsolved

StreamNative's architecture reflects the realities of enterprise cloud-native infrastructure. Each layer independently creates risk. Together, they create a governance crisis.

Multi-Cloud Policy Sprawl

With workloads distributed across AWS, GCP, Azure, and Alibaba Cloud — and edge traffic filtered through Cloudflare — security and rate-limit policies are defined four times over, in four different formats, by four different teams. Any drift between them creates an exploitable gap.

AWS GCP Azure Alibaba Cloud Cloudflare

Heterogeneous Broker Chaos

Apache Kafka, Apache Pulsar, and Amazon Kinesis each have distinct schema registries, consumer models, and auth mechanisms. There is no shared catalog of who is consuming which topic, no consistent rate limiting, and no unified audit trail — creating invisibility at the data layer.

Apache Kafka Apache Pulsar Kinesis Schema drift

Service Mesh Integration Gaps

Istio and Envoy govern East-West traffic inside the cluster, but have no awareness of the API and event-stream layer above them. Policies set in the service mesh are invisible to the API gateway — and vice versa — leaving East-West and North-South traffic operating in separate governance silos.

Istio Envoy East-West traffic mTLS gaps

Capability 1

Unified Multi-Cloud Governance

Gravitee acts as the single source of truth for all API and event-stream policies across StreamNative's entire cloud footprint. Policies written once propagate instantly to AWS API Gateway, GCP Apigee, Azure API Management, and Alibaba Cloud — while synchronizing with your Cloudflare WAF rules and Istio service mesh AuthorizationPolicies simultaneously.

  • Cloudflare sync: Gravitee policy changes propagate to Cloudflare WAF rules automatically — zero manual firewall updates.
  • Istio AuthorizationPolicy bridge: API gateway decisions are reflected as Istio policies, closing the East-West / North-South gap.
  • Envoy xDS integration: Gravitee pushes route and rate-limit config to Envoy sidecars via the xDS control plane API.
  • Zero-drift enforcement: A single policy YAML is the authoritative source — no per-cloud translation scripts, no config divergence.
gravitee-policy.yaml — propagating to 4 clouds 
# Gravitee policy — applies to ALL environments
apiVersion: gravitee.io/v1alpha1
kind: ApiV4Definition
metadata:
  name: streamnative-global-policy
spec:
  targets:
    - aws-us-east-1
    - gcp-us-central1
    - azure-eastus
    - alibaba-cn-hangzhou
  flows:
    - name: edge-security
      policies:
        - type: JWT_VALIDATION
          jwks_uri: https://auth.streamnative.io/jwks
        - type: RATE_LIMIT
          limit: 50000
          period: MINUTE
  meshSync:
    cloudflare: enabled
    istio:
      enabled: true
      namespace: production
    envoy:
      xds: true
# ✓ Deployed  ✓ Cloudflare sync  ✓ Istio sync
Capability 2

Event-Stream Management

Gravitee's event-native gateway treats Kafka topics, Pulsar subscriptions, and Kinesis streams with the same first-class API management they deserve. Native wire-protocol support means producers and consumers connect without any client-side changes — while Gravitee enforces schema validation, rate limits, ACLs, and SASL/mTLS authentication transparently at the gateway layer.

  • Kafka native gateway: Full Kafka wire protocol — ACLs, quotas, and schema validation without client modification.
  • Pulsar & StreamNative Cloud: Topic autodiscovery, per-subscription rate limits, and schema registry enforcement.
  • Unified schema catalog: Avro, Protobuf, and JSON schemas centralized — breaking changes blocked before they reach consumers.
  • Single developer portal: Kafka topics, Pulsar namespaces, and Kinesis streams discoverable alongside REST APIs — with self-serve subscriptions.

Capability 3

Automated Compliance

Gravitee enforces GDPR, HIPAA, and FedRAMP controls at the API and event-stream layer — without requiring engineers to manually implement compliance logic. Deep integrations with Okta for identity and OpenTelemetry for distributed tracing provide the audit evidence regulators require, automatically.

  • Okta integration: OIDC/SAML token validation and SCIM-driven role enforcement — identity is the policy source of truth.
  • OpenTelemetry audit trail: Every API call and event-stream access emits a W3C-compliant trace — ready for SIEM ingestion.
  • Data residency enforcement: GDPR data-locality policies block cross-region data flows at the gateway — no application code changes.
  • FedRAMP controls mapping: AC-2, AU-2, and SI-3 controls implemented as Gravitee policies — auditor-ready evidence generated continuously.
